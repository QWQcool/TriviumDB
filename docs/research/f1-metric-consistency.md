## 0. 摘要：**这不是"修好了一个 bug"，而是一个数据依赖的 trade-off**

**结论先行**：`sign_info`（D1 的逐坐标符号熵）**完美预测** F1 的收益符号 ——
符号面活着的数据集（`sign_info ≥ 0.75`）**全部受益**，符号面死掉的数据集（`sign_info = 0.000`）**全部受损**。

| 数据集 | dim | `sign_info` | **OFF**（cheap 导航） | **ON**（weighted 导航） | **Δ @ef_s=128** | Δ @ef_s=1024 | QPS 代价 |
|---|---|---|---|---|---|---|---|
| **glove100** | 100 | 0.946 | 45.57% | **67.37%** | **+21.80** | +17.75（71.66→**89.41**） | −1.3% |
| **gauss960** | 960 | 1.000 | 0.81% | **2.34%** | **+1.53**（**2.9×**） | +10.64（5.85→16.49） | −4.4% |
| **wolt_clip** | 512 | 0.836 | 77.76% | **78.67%** | **+0.91** | +0.61 | −2.4% |
| **cohere** | 768 | 0.747 | 97.55% | **98.02%** | **+0.47** | +0.08 | −3.6% |
| gist960 | 960 | **0.000** | 2.86% | 1.61% | **−1.25** | −0.60 | 噪声级 |
| **sift128** | 128 | **0.000** | 21.79% | **8.42%** | **−13.37** | **−26.09**（47.20→21.11） | −8.8% |

**⇒ 上游把 L0 查询导航设成 cheap 并不是单纯的疏漏：它是符号面退化数据上的一种保护。**
但反过来，对符号面健康的数据（= 绝大多数真实嵌入），加权导航是**更好的**——在 glove100 上值
**+21.8pp**，比论文自己的任何优化都大。

**⇒ 正确的结论是"按数据的符号面状态选择导航度量"**，而**做这个判断的量与 D1 判据链的 ① 是同一个**
（`sign_info`）—— 于是「该不该去均值」与「该用哪个导航度量」由**同一个几秒钟可算的诊断**决定。

## 1. 补丁内容（默认路径零改动）

### 1.1 `src/index/bq.rs` —— 新增开关（沿用仓库既有 `LazyLock<bool>` + env 模式）

```rust
pub(crate) static NAV_WEIGHTED: std::sync::LazyLock<bool> =
    std::sync::LazyLock::new(|| std::env::var("TRIVIUM_NAV_WEIGHTED").is_ok_and(|v| v == "1"));
```

### 1.2 `src/index/quiver.rs` —— **3 处导航点**全部跟随开关

| 位置 | 函数 | 说明 |
|---|---|---|
| `beam_search_l0_impl` 的 `cheap_distance` 闭包 | 主路径（`search_flat` 走这条） | **384 维分支必须一起切**，否则该维度下开关失效（第一稿差点漏掉） |
| `beam_search_l0_dual` 的 `distance` 闭包 | dual / 信号（TSNG）路径 | 不同步会让两条路径度量不一致 |
| `beam_search_l0_384_with_scratch` 的 `distance` 闭包 | 384 维 scratch 路径（第三个导航点） | 同上 |

开关值在函数入口取一次到局部变量（热路径不反复读 atomic）。

### 1.3 `src/tsng.rs` —— 截断上界随开关变化

`TsngNavigationScorer::new` 的 `max_bq_distance` 原本固定 `2·dim`（Hamming 上界）。
加权距离的上界是 `4·dim` ⇒ 若不变，开关打开时**所有 TSNG 距离会被截断到饱和**：

```rust
let per_dim = if *crate::index::bq::NAV_WEIGHTED { 4 } else { 2 };
```

### 1.4 为什么默认**关闭**
1. 默认路径逐位不变 ⇒ **所有冻结值仍是回归守卫**（已实测，见 §1.5），
2. 可在**同一二进制**里做 A/B（消除跨编译差异），
3. 是否翻转默认值应由上游决定（它对 sift128/gist960 类是**负收益**）。

## 3. 机制解释（为什么符号面决定 F1 的符号）

BQ2 距离的两个口径：

```
cheap    : Hamming(pos) + Hamming(strong)                    ← 无偏，不依赖 |h|
weighted : 4·dim − <w_a,w_b>,  w = (2p−1)(1+s) ∈ {−2,−1,1,2}
           = 3·dim − (3/2)(|h_a|+|h_b|) + Ham(strong)/2       （全非负退化式）
                    ↑ 含一个与 |h| 成正比的**偏置项**
```

- **符号面活着**（`p` 有信息）：`<w_a,w_b>` 里的符号分量携带真实相似度信息 ⇒ 加权度量**更有分辨力**
  ⇒ 用它导航 ⇒ 走到更对的邻居（glove100 **+21.8pp**、cohere +0.47、CLIP +0.91）。
- **符号面死掉**（gist960/sift128：`p` 逐坐标恒定）：加权式只剩
  `3·dim − (3/2)(|h_a|+|h_b|) + Ham/2` ⇒ 排序被 **`|h|` 偏置主导**（实测偏置 +3.34σ），
  即"优先选 popcount 小的邻居"——**这正是 p1 诊断出的崩塌机制**。
  此时用加权导航 = **把偏置同时用于建图和导航**，加倍放大 ⇒ sift128 **−13.4pp**。
  cheap 导航因为**不含 `|h|` 偏置**，反而部分抵消了建图侧的偏置 ⇒ 上游的默认值是有道理的。

⇒ **一个度量不可能对两类数据都好**；必须按数据选。

## 4. 条件化建议（与 D1 判据链合并）

```
① sign_info < 0.2  ⇒  去均值（D1）**+** 保持 cheap 导航（若不能去均值）
   ── 去均值后 sign_info 回到 ~0.98 ⇒ 此时再打开 weighted 导航（应再增益，**待测**）
② sign_info ≥ 0.6  ⇒  打开 TRIVIUM_NAV_WEIGHTED=1（glove100 +21.8pp、cohere +0.5pp，代价 ≲4% QPS）
```

**新的待测项（U19）**：`去均值 + weighted 导航` 的组合臂
（`gist960c`/`sift128c` 的 `sign_info ≈ 0.92–0.98` ⇒ 按 ①→② 的链，应当在去均值后再开加权导航）。
这是 §4 表格里唯一还没实测的格子。

## 5. 限制

| # | 限制 |
|---|---|
| L1 | **只测了 `ef_c=128` 一个建图束宽**；其它 `ef_c` 可能改变 Δ 的绝对值（不改变符号，机制如此） |
| L2 | **TSNG 的多信号路径未测**（只改了它的截断上界以保证不变形） |
| L3 | QPS 是**单次估计**；gist960 上抖动达 ±20% ⇒ 只应引用"≲9%"这一量级 |
| L4 | 单机、**无 AVX-512**（本机 `Avx512F=False`）⇒ 加权导航的相对代价在 Zen4+ 上可能不同（cheap 有 `bq2_distance_cheap_avx512*` 专用内核，加权没有） |
| L5 | `gauss960` 的绝对增益（+1.5pp @128）远小于 P1 的**码 oracle 上界**估计（0.83→≤54.45）：因为该上界是"导航完全正确"的理想值，**不是 F1 的上界**（F1 不改图，图在随机数据上本身就坏）。⇒ **前文把 oracle 值当作 F1 收益上界是不准确的**（已在 `t2-gist960-collapse.md` 标注） |
| L6 | 未测 `wolt_clipc`/`gist960c` 等**去均值臂**（U19） |
