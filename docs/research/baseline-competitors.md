# 竞品基线 —— hnswlib / FAISS HNSW / USearch / IVF 的独立核验

> **目的**：仓库宣称"相对 hnswlib 4–5×"，但**该数字在本机从未被复现过**（L1 阶段遗留的最大缺口）。
> 任何方向的论文都绕不过"有无可比基线"。
>
> **基准**：`scripts/research/baseline_competitors.py`（新增）
> **状态**：已完成，cohere 与 SIFT 双数据集。**零 `src/` 改动。**

## 0. ★ 裁定：**这是本次工作第一个正向结论**

| 数据集 | 裁定 |
|---|---|
| **cohere-768** | **仓库的宣称成立**：QuIVer 在 matched recall 下比三个 HNSW 实现快 **4.1–5.0×**，比 IVF-Flat 快 **72×**；建图还快 **5.3×** ✅ |
| **SIFT-128** | **完全失效**：QuIVer 的召回**天花板只有 47.21%**，而 hnswlib 在 ef=64 就有 97.46% 且**更快**（45,118 vs 18,247 QPS）⇒ **严格被支配** ❌ |

**⇒ 核心结论：QuIVer 的优势是"高维条件优势"，而不是普遍优势。**
在 768 维上它是当前最优之一；在 128 维上它不是一个可用的索引。

## 1. 口径（与 QuIVer 主基准严格对齐）

| 项 | 值 |
|---|---|
| 数据 | L2 归一化后 cosine = 内积 |
| 参数 | `M=32`、`ef_construction=128`（对齐 QuIVer 的 `m=32 / ef_c=128`） |
| 扫描 | `ef_search ∈ {64,128,256,512,1024}` |
| 线程 | **32**（与 QuIVer 主基准一致） |
| 召回 | 返回 top-10 命中 GT top-10 的比例（与 QuIVer 一致） |
| 正确性自检 | `faiss_exact` 在 cohere 上 **100.00%**、SIFT 上 **99.94%**（后者为 f32 分数并列所致）⇒ 度量管线正确 ✅ |

> **公平性声明**：`M=32` 对齐 QuIVer 的 `m`。出度语义上 QuIVer 的 `m0 = 2m = 64`
> 与 HNSW 的层 0 上限 `≈2M = 64` **可比**。

- QuIVer 的召回**天花板是 47.21%**（ef_s=1024，18,247 QPS）

- 三个 HNSW 实现的最低召回都在 **96.9%** 以上，**从不进入 QuIVer 能达到的召回区间**
  ⇒ 两者曲线**没有交点** ⇒ hnswlib/FAISS/USearch **严格支配** QuIVer

**⇒ 在 SIFT-128 上，QuIVer 不是"更慢"，而是"不可用"。**

> ⚠️ **（2026-09-17 措辞更正）** 上文与 §2 中"SIFT 召回**天花板** 47.21%"应读作
> **"实用 ef 上限"**，而不是硬上限。已发表版本（PVLDB Vol. 20, 2027；arXiv `2605.02171`）
> 的 **Finding 2** 明确指出：**12 个数据集（含最差的 Random-Sphere / GIST-960）上 recall 都随 `ef` 单调上升，
> 未观察到天花板**——加宽搜索总能找回真邻域，代价是 `ef` 大到不实用。
> 我们的实测与之**一致**（SIFT：`ef_s = 64→1024` 时 `15.77% → 47.23%` 单调上升）。
> **结论不变**（在可用 `ef` 区间内被 hnswlib 严格支配：`ef=64` 时 `15.77%` vs `97.46%`），
> 但"天花板"一词是错的，后续引用请改用"实用 ef 上限"。
> 详见 `paper-readiness.md` §0.2 / §3-C6。

## 4. 机制：为什么是高维条件优势

来自 `t2-sift-crosscheck.md` 的诊断（GT 独立重算 100% 一致 ⇒ 非数据问题）：

| 指标 | cohere-768 | SIFT-128 | 影响 |
|---|---|---|---|
| **可分性 = (GT1−GT10)/cos_std** | **0.796σ** | **0.129σ** | SIFT 的 top-10 排序所需精度高 6× |
| BQ2 签名总长 | **1536 bit**（12 chunk） | **256 bit**（2 chunk） | SIFT 可用的信号少 6× |
| 随机对 cos 标准差 | 0.0471 | 0.2109 | SIFT 的相似度分布宽 4.5× |

**⇒ 需求（0.129σ）上升 6× 的同时供给（256 bit）下降 6×，
两个 6× 叠加，构成 QuIVer 在低维上的失效。**

**且这不是 f32 精排能补救的**：`search_flat` 的精排是精确的，
但**它只能修正已进入候选集的点**；问题是 BQ2 图在导航阶段就把真 top-10 丢在了候选集之外。

## 5. 论文形状（重要的战略更新）

在本次会话之前，全部结果都是负的（T1 / T2 / TSNG）。
**本报告给出了第一个正向、可复现、有机制的结论**，且它同时携带一个清晰的边界：

> ### 候选论文核心
> **「BQ2 签名图索引的精度-维数边界：在 768 维上比三个 HNSW 实现快 4–5×、建图快 5.3×，
> 但在 128 维上召回天花板仅 47%，被 HNSW 严格支配；边界可由
> top-k 可分性与签名长度的比值预测」**

该主张具备论文所需的要素：

| 要素 | 现状 |
|---|---|
| **正向贡献** | ✅ 4.1–5.0× 加速（三个独立 HNSW 实现 + IVF + 精确基线，同机同口径） |
| **可证伪边界** | ✅ SIFT-128 上 47.21% 天花板，严格被支配 |
| **机制解释** | ✅ 可分性 × 签名长度，两个 6× |
| **可操作结论** | ✅ 低维数据应按维数提升 bit/维，或直接拒绝 |
| **必守守卫** | ✅ 精确基线 100.00% / 99.94% 自检 |

**仍缺**：数据集只有 2 个（需补 **GIST-960 或 glove-100** 来钉住维数轴的中点与低维端）、
硬件只有 1 台（无 AVX-512）。

## 6. 限制与未知

| # | 项 | 说明 |
|---|---|---|
| **L1** | 只扫了一个 M（32） | HNSW 的 M 未调优；M=16/48 可能改变倍差。**但三个独立实现一致给出 4.1–5.0×，说明量级稳** |
| **L2** | 未调优 `ef_construction` | 已实测 `ef_c=64` 可省 1.55× 建图（见 `t2-b2-result.md`） |
| **L3** | 单机、无 AVX-512 | 与全部前序工作同口径 |
| **L4** | SIFT 走了"L2 归一化 + cosine"的非标准协议 | 不可与公开 SIFT-L2 数字对比；但**仓库内部两数据集口径一致**，不影响本报告的对比 |
| **L5** | 未测内存 | QuIVer 的 Hot 675 MiB(cohere) / 522 MiB(SIFT)；HNSW 的内存未记录 |
