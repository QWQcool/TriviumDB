### 三个改变计划的发现

**① 本机没有 AVX-512（实测，非推断）。** i9-14900K 上 `#[cfg(target_arch="x86_64")]` 的 `distance_avx512` 分支永不执行，实际走 `bq2_distance_raw_avx2`（AVX2 无字节 popcount，需 nibble-LUT 查表）。论文硬件是 Zen4 7840HS（含 AVX-512 VPOPCNTDQ）。→ **绝对 QPS 不可与论文对拍，本研究只用同机 A/B 比值。**

**② `bench_rbq2_precision` 与 `bench_cohere1m` 的数据口径不一致。** `prepare_all.py` 的 `hf_bin` 路径（`:303-328`）**不做 L2 归一化**，而 `process_hdf5`/`process_huggingface` 都调了 `l2_normalize`。`bench_cohere1m` 内部自己补了归一化（`:477`），但 `bench_rbq2_precision` 直接用原始未归一化数据（`:373/:379/:413`）。

**③ ★ 现有 RaBitQ 基线是无效对照，不能用来支撑"BQ2 优于 RaBitQ"。** 详见 §6。两处硬伤：
- **位预算不对等**：BQ2 = 2 bit/维，RaBitQ 只给 1 bit/维。而编码消融证明 1→2 bit 带来 **+8.7pp** Recall@10。
- **逐向量因子与尺度不变度量不匹配**：`f_rescale = -‖x‖²/(0.5‖x‖₁)` 把模长信息注射进 cosine 排序，把 asym 从 53.30% 压到 **23.35%**。

**④ 旋转在 Cohere-1M 上是显著负增益。** 配对 t = **−5.41**、符号检验 **p ≈ 2×10⁻⁶**（104 条变差 vs 46 条变好）。且**旋转的代价（−6.2pp）大于整整一个比特的收益（+2.5pp）**。这在合成各向同性高斯数据上依然为负（−1.45pp），故不是"数据非各向同性"导致的。

> **对 T1 的直接结论**：RaBitQ 不能作为"替换 BQ2 以提升召回"的路径。它的价值必须重新定位为**有界误差估计 → 导航可靠性信号**（正是 TSNG 目前缺失的能力）。详见 §7。

### 1.2 SIMD 路径实测

用 .NET intrinsics 直接查询（`[System.Runtime.Intrinsics.X86.Avx512F]::IsSupported`）：

| 特性 | 本机 | 论文硬件 | 本仓库对应代码 |
|---|---|---|---|
| AVX-512F | **False** | ✅ | — |
| AVX-512 VPOPCNTDQ | **不可用** | ✅ | — |
| AVX2 | **True** | ✅ | `bq2_distance_raw_avx2`（`src/index/bq.rs:621`） |

**实际生效的距离内核**（`src/index/bq.rs:149-188` 派发链）：

```
dim % 64 != 0                 → distance_scalar            (bq.rs:192)
AVX-512 VPOPCNTDQ + AVX-512F  → distance_avx512            ← 本机永不进入
AVX2                          → bq2_distance_raw_avx2      ← 本机实际路径
aarch64 NEON                  → bq2_distance_raw_neon
其他                           → distance_scalar
```

同理 `distance_to_sig_cheap`（`bq.rs:1045`）回退到标量 XOR+popcount（`bq.rs:1073-1079`）。

**为什么这很重要**：AVX2 没有字节/字 popcount 指令，只能靠 nibble（4-bit）查表 `pshufb`；AVX-512 VPOPCNTDQ 有硬件 popcount。对 QuIVer 这种 popcount 密集负载，两者差距可达数倍。**本机测得的 QPS 一定低于论文，且低多少无法在本机量化**（`TRIVIUM_NO_AVX512=1` 在此是 no-op，因为 AVX-512 分支本就不可达）。

→ **口径决策**：本报告所有 QPS 仅用于**同机 A/B 对比与曲线形状**，不用于与论文绝对值对拍。

### 1.3 平行扩展特性（P-core + E-core 异构）

| 线程数 | QPS | 相对 1 线程 |
|---|---|---|
| 1 | 4,705 | 1.0x |
| 2 | 10,705 | 2.3x |
| 4 | 17,534 | 3.7x |
| 8 | 35,605 | 7.6x |
| 16 | 52,293 | 11.1x |
| 32（含 HT） | 59,653 | **12.7x** |

24 物理核只换来 **12.7x**（满分应 ~24x）。原因是 16 个 E-core 单核性能明显低于 P-core，且 `StripedSpinLocks`（`quiver.rs:225`）在反向边剪枝上是主要争用点。**报告扩展性时必须显式标注 CPU 拓扑**，否则与论文的 16 线程 Zen4 不可比。

## 2. 数据集核查

### 2.1 实际规模 ≠ README 暗示

`python scripts/prepare_all.py cohere` → `process_hf_bin` 从 `YoKONCy/Cohere-1M-wikipedia-768d` 下载 3 个文件（139 s，~3.1 GB）：

| 文件 | 实际大小 | 实际规模 | README_QUIVER 表格暗示 |
|---|---|---|---|
| `cohere_train.f32` | 3,072,000,000 B | **1,000,000 × 768** ✓ | 1M ✓ |
| `cohere_test.f32` | 3,072,000 B | **1,000 × 768** ⚠️ | "10K queries" 不符 |
| `cohere_groundtruth.i32` | 4,000,000 B | **1,000 × 1,000**（K=1000）⚠️ | — |

`bench_cohere1m` 对 K 的处理是稳健的：`k_gt = gt_data.len() / n_test`（`:298`）动态推导，断言 `k_gt >= EXACT_TOP_K`（`:299`），只取前 10 列（`:443`）。所以 K=1000 不破坏 Recall@10。

**但要记录副作用**：查询集只有 **1000 条**，比论文描述的 10K 少一个数量级 → Recall 估计的统计误差更大。本文所有 recall 数字的 SE 约 **±1.3pp**（200 查询配对测试实测：无旋转 59.50% 的逐查询 SE = 1.31pp）。

### 2.2 Ground Truth 自校验（A6 步骤）

`scripts/research/l1_validate_dataset.py`：

```

GT 前 500 行重复索引行数          : 0

  逐条 top-10 重合数              : [10] × 20
  平均重合                        : 10.00 / 10

```

→ **GT 可信，可作 ground truth 使用。**

### 2.3 ⚠️ 数据未做 L2 归一化

`scripts/research/l1_check_norms.py`：

```
train  ||x||2 : min=12.3238  max=16.6572  mean=13.8005  std=0.6034
       ||x||1/||x||2 = 17.6507   （各向同性期望 22.1116）
       是否近似单位向量: False
test   ||x||2 : min=12.3428  max=16.2247  mean=13.8302  std=0.6165
```

两条结论：
1. **模长波动 ±4.4%**（CV = 0.0436）→ 任何依赖 `‖x‖` 的逐向量因子都会引入偏差。
2. **`‖x‖₁/‖x‖₂ = 17.65 < 22.11`** → 数据分布**非各向同性**（比高斯更"尖峰"），这是后面解释旋转失效的关键前提。

`prepare_all.py` 的两条路径处理不一致，属**流水线缺陷**（应统一或显式声明）：

| 路径 | 函数 | 是否 L2 归一化 |
|---|---|---|
| `hdf5` | `process_hdf5`（`:204`） | ✅ `l2_normalize`（`:222-223`） |
| `huggingface` | `process_huggingface`（`:236`） | ✅ `compute_groundtruth` 内归一化（`:153-154`） |
| **`hf_bin`** | `process_hf_bin`（`:303`） | ❌ **只下载拷贝** |

这与 Vamana 文献的常规结论（α>1 放宽剪枝能提升 recall）**相反**。可能原因（需消融确认）：
1. `vamana_select` 在选不满 `max_k` 时**按距离序补足**（`quiver.rs:1656-1668`），α>1 会让剪枝更宽松地接受候选，再被补足逻辑灌入低质量边，稀释图质量。
2. 建图期额外注入的随机采样候选（`quiver.rs:652-662`）在 α>1 下更容易留进图。
3. Cohere 数据的"尖峰"分布下，α-diversity 假设（欧氏三角不等式语义）与归一化 cosine 目标不完全匹配。

> **对 T2（PiPNN）的意义**：α=1.0 更优、且建图更慢（42.5 s vs 36.9 s）说明**当前 α>1 路径可能在用"更多边"补偿"更差的选择"**。做分区式构建时必须重新标定 α，不能沿用论文的 1.2。

## 6. ★ T1 前置发现：现有 RaBitQ 基线不成立

这一节是本次 L1 最重要的产出。它**否决了原计划的 T1 路径假设**，并把它重定向到一个更可发表的方向。

### 6.1 基准原始输出

`cargo bench --bench bench_rbq2_precision`（100K × 768，200 查询）：

```
K          BQ2(2bit)   RBQ-sym   RBQ-asym
1            66.50%     35.50%     21.00%
10           61.90%     41.00%     23.35%
100          58.94%     39.40%     18.17%
500          59.21%     42.46%     19.56%
```

### 6.2 红旗 1：位预算不对等

由 §5.3 已知 1 bit→2 bit 值 +8.7pp。而本基准给 **BQ2 = 2 bit/维**、**RaBitQ = 1 bit/维**。→ "BQ2 胜 RaBitQ" 的第一近似解释就是"比特多一倍"，**结论不可用**。

### 6.3 红旗 2：`RBQ-asym < RBQ-sym`（23.35% < 41.00%）

RaBitQ 的核心贡献正是**非对称距离估计（ADC）优于对称 Hamming**。asym 反而更低说明实现有问题。逐步定位（`scripts/research/t1_verify_asym.py`）：

| 变体（100K/200Q/K=10） | top-10 重合 |
|---|---|
| ① 1-bit 旋转 + **去掉**逐向量因子 | **53.30%** |
| ② 基准 `f_rescale = -‖x‖²/(0.5‖x‖₁)` | **23.35%** ← **与 Rust 基准逐位一致** |
| ③ RaBitQ 式 `f = ‖x_u‖₁/D` | 45.80% |
| （BQ2 2-bit 参照） | 61.90% |

> ② = 23.35% 与 Rust 基准完全一致 → **numpy 复刻忠实，拆分结论可信**。

**根因：度量不匹配。** cosine 是**尺度不变**的，而 `f_rescale` 依赖 `‖x‖²/‖x‖₁`，把模长信息（CV = 4.4%）注射进排序。①（无因子，53.30%）> ③（RaBitQ 式因子，45.80%）> ② （基准因子，23.35%）说明：**在未归一化数据上，任何 per-vector 因子都有害**；正确做法是**先归一化再量化**，此时因子退化为常数。

配套证据：`src/../benches/bench_rbq2_precision.rs:271` 把 `f_add` 硬编码为 `1.0`（作为"1 − IP"的常数项，本身正确），而 `f_rescale`（`:272-276`）是唯一的数据依赖项——它的构造决定了排序质量。

### 6.4 旋转本身是合法的正交变换（已证）

`scripts/research/t1_verify_rotation.py` 逐位复刻 `bench_rbq2_precision.rs:36-110` 的 `FhtKacRotator`：

```
dim=768  padded_dim=768  trunc_dim=512  fac=0.04419417
（trunc_dim != padded_dim → 走 else 分支）

判据1 范数保持: ||R(x)||/||x||  min=1.000000  max=1.000000  → PASS
判据2 内积保持: <Rq,Rx> vs <q,x>  相对误差 mean=0.000000  max=0.000000  → PASS
```

→ 旋转**不是 bug**。它精确保持范数与内积，是一个合法的结构化正交变换（4 轮随机翻转 + FHT + Kac's walk，净缩放 4 × 0.25 = 1）。

### 6.5 ★ 等比特预算下旋转是负增益（配对显著）

`scripts/research/t1_equal_bits.py`（100K / 200Q / K=10）：

| 配置 | top-10 overlap |
|---|---|
| 1-bit sign，**无旋转** | **59.50%** |
| 1-bit sign，有旋转 | 53.30% |
| 2-bit SM，**无旋转**（= BQ2） | **61.95%**（与基准 61.90% 吻合 ✓） |
| 2-bit SM，有旋转 | 58.95% |
| 2-bit SM，有旋转 + L2 归一化 | 58.95%（归一化对 SM 无影响——编码本身尺度不变） |

**旋转的代价（−6.2pp @1bit，−3.0pp @2bit）大于整整一个比特的收益（+2.5pp）。**

配对显著性检验（`scripts/research/t1_significance.py`）：

```
无旋转 Recall@10 = 59.50%   (逐查询 SE = 1.31pp)
有旋转 Recall@10 = 53.30%   (逐查询 SE = 1.25pp)
配对差 mean = -6.20pp        (配对 SE = 1.15pp)
配对 t 统计量 = -5.41        (|t| > 1.97 即 p < 0.05 双尾)
旋转变好 46 条 / 变差 104 条 / 持平 50 条
双侧符号检验 p ≈ 0.000002    (n_eff = 150)
```

→ **统计显著，非噪声。**

### 6.6 排除"数据非各向同性"这一解释

`scripts/research/t1_isotropy_test.py` 用合成数据重做同一对比（50K / 200Q / K=10）：

| 数据 | `‖x‖₁/‖x‖₂` | sign 无旋转 | sign 有旋转 | 旋转净增益 |
|---|---|---|---|---|
| 各向同性高斯 | 22.119（期望 22.112） | 21.45% | 20.00% | **−1.45pp** |
| 低秩+尖峰 | 22.123 | 77.25% | 77.10% | −0.15pp |

→ **即使在完全各向同性的理想数据上，旋转也没有带来 RaBitQ 理论预期的增益**（−1.45pp 在 200 查询噪声范围内）。所以旋转失效**不是**因为 Cohere 非各向同性。

**解释（待理论化）**：无旋转时 `sign(x)` 直接编码原始坐标，而 embedding 的坐标轴本身携带语义（多数 embedder 有固定的"语义方向"）；随机旋转把这种结构抹平为近高斯分布，1 bit 的信息量反而下降。这**恰好正面支持 QuIVer 论文"training-free / 无旋转"的设计主张**——这是本仓库可以据以立论的实证。

### 6.7 另一个流水线缺陷：数据未归一化

`prepare_all.py:303-328` 的 `hf_bin` 路径不做归一化，而 `bench_cohere1m` 内部补了（`:477`）、`bench_rbq2_precision` 没补。这使**两个基准的输入口径不一致**，是跨基准比较的隐患。已记入遗留项。

## 7. 对研究路线的影响

### 7.1 T1（RaBitQ 融合）必须重写叙事

| 原假设 | L1 实证 | 新定位 |
|---|---|---|
| RaBitQ 量化比 BQ2 精度更好，可替换 | ❌ 等比特下旋转为负增益（§6.5，p≈2e-6）；BQ2 的 2-bit SM 已是强基线 | RaBitQ 的价值**不是**召回，而是**有理论界的距离估计** |
| 用 RaBitQ 的量化码替换 `Bq2Signature` | ⚠️ 技术上可行（改动半径见摸底报告 T1），但预期收益为负 | 改为**并行新增**一个 ADC scorer，用于**导航可靠性**而非主距离 |
| — | — | **新主线**：把 RaBitQ 的误差界作为 TSNG 的**导航信号**（`TsngSearchMetrics` 目前完全没有误差/置信度字段） |

**新的 T1 命题（建议）**：
> 用 RaBitQ 的有界误差估计为图导航提供**可证明的剪枝准则**——当估计误差上界小于当前 top-k 阈值时提前终止。这把 RaBitQ 从"更准的量化器"变成"**可证明的早停/剪枝控制器**"，与 TSNG 的"三信号导航"天然互补（误差界 = 第四路信号，且是唯一有理论保证的一路）。

这条路径的好处：
- 不需要在召回上打败 BQ2（已证明很难），只需在**同等召回下减少距离计算量**——这是可证明的、审稿人容易接受的贡献。
- 直接填上摸底报告 §3.2-F 指出的"无 L 层级理论量"空白。
- 与 PiPNN（T2）正交，可并行推进。

### 7.2 T2（PiPNN 分区式构建）证据增强

L1 为 T2 提供了三条新的实证支撑：

1. **`α=1.0` 优于论文默认的 1.2**（§4.3，ef=32 处 +4.2pp）→ 分区构建后 α 必须重新标定，不能沿用。
2. **内存是主要瓶颈**：Hot 708 B/节点，其中 **Layer0 邻接表占 516 B（73%）**，BQ 只占 192 B（27%）。m=64 时 Hot 涨到 1,163 MB。→ **PiPNN 按分区压缩邻接表是内存维度的直接收益点**。
3. **增量路径未优化**：摸底报告 R4 指出 `insert`（`quiver.rs:1033`）每条反向边跑全量 `vamana_select`（O(m0³·C)），而批量路径已改惰性剪枝（`quiver.rs:755-805`）→ **分区化对增量写入的收益最大**。

### 7.3 建议的路线重排

| 优先级 | 事项 | 依据 |
|---|---|---|
| **P0** | 修正 `bench_rbq2_precision`：① 加 L2 归一化 ② 实现 RaBitQ 2-bit（等比特） ③ 修 `f_rescale` 为归一化后的正确形式 | §6.2–6.6；不做这一步后续所有 RaBitQ 结论都不可信 |
| **P0** | 补测 `bench_recall_at_k` / `bench_variance`（本次未跑完） | L1 完整性 |
| **P1** | **T1 重定向**：RaBitQ 误差界 → 导航可靠性信号（新命题） | §7.1 |
| **P1** | 消融确认 `α=1.0` 更优的机理（疑与 `vamana_select` 补足逻辑 `quiver.rs:1656-1668` 有关） | §4.3 |
| **P2** | 在**各向同性数据集**（`bench_random_sphere`）上复测旋转增益 | §6.6 的合成实验需真实数据集佐证；若 sphere 上旋转为正，则结论变为"旋转收益取决于数据各向同性" |
