# V1 / V1b — 5-bit RaBitQ 误差界剪枝的端到端 trade-off 实测（T1 裁定实验）

> **回答的问题**（`t1-epsilon-scaling-decision.md` §7.1 V1）：
> 可证剪枝需 5 bit/维（BQ2 是 2 bit/维，码长 2.5×），在那预算下 §3 测得的剪枝率是 72%。
> 但 5 bit 码的**带宽/解包成本**是否会被剪枝收益抵消？"不能用推断，必须实测"。
>
> **V1b 追加**：把界用在**展开剪枝**（而非候选剪枝）上是否可行？—— 用于关闭整个
> "界驱动剪枝"家族，避免"换一种剪法就能行"的残念。
>
> **基准**：`benches/bench_pruning_tradeoff.rs`（新增，6 配置）
> **前序**：`bootstrap-report.md` → `l1-baseline.md` → `l1-followup.md` → `t1-epsilon-scaling-decision.md`
> **分支**：`research/quiver2-pipnn-rabitq-tsng`　**源码改动**：无（仅新增 bench + `Cargo.toml` 注册）

## 0. 裁定

**T1 的"界驱动剪枝"路线（候选剪枝与展开剪枝**两者**）在内存驻留的图遍历场景下不成立，
三个独立原因各自足以致命：**

| # | 原因 | 证据 |
|---|---|---|
| **R1** | **候选剪枝能力不可迁移**：§3 的 72% 是在 **10 万个原始候选**上测的（绝大多数候选很远、易于剪掉）；而图遍历的精排候选集**已经是最近的 `ef` 个**，它们的误差区间彼此重叠 → 实剪枝率 **0.0–0.6%**，不是 72% | 精排保留率 **99.4–100%** |
| **R2** | **成本倒挂**：5-bit 估计量 **435 ns/次** 比它想省掉的 f32 精确内积 **313 ns/次** 还慢 39%。"先算界、再决定要不要做 f32"本身即亏本 | 内核微基准（独立于遍历，最硬） |
| **R3** | **展开剪枝结构性失效**：判据 `U(u) < θ` 需 `ε < θ − est_u`，而实测 **`θ − est_u < 0`**（−0.019 ~ −0.049）⇒ **即使 ε = 0（无限精度码）也无法触发**。判别力 **0.00–0.10%**，比 R1 还低一个数量级 | V1b（E1/E2，§3.4） |

> **R3 是三者中最强的**：R1/R2 说"当前码不够好/太贵"，R3 说"**换任何码都不行**"——
> 失效源于遍历的堆序结构（frontier 弹出的必然是 est 最高的未展开节点，
> 而它按构造几乎是 Top-k 的候选者），与量化精度**正交**。

R2 的因果很清楚：5-bit 解包 768 个坐标是**标量**活（移位+掩码+转换），而 f32 点积能被 AVX 向量化（每指令 8 个 float）。**在 SIMD 优化更彻底的实现里，这个差距只会更大。**

→ **T1 的定位必须再退一步**：不能在"内存驻留 + 图遍历"里靠误差界省距离计算。
唯一可能成立的场景是 **f32 层不在内存驻留**（SSD/冷层），此时 f32 精排的代价高几个数量级，
码的 480 B vs 3072 B 流量优势才可能翻盘 —— 而这**恰好是本仓库的冷热分离设计前提**（见 §5）。

## 1. 实验设计

### 1.1 关键认识：剪枝能省什么、不能省什么

在图遍历里，"距离计算"**本身就是**产生 `est` 与 `ε` 的那一步（`ε` 是码的性质，随 `est` 一同算出）。
因此**剪掉一个候选省不下那次计算**。

真正能省的只有一处：**昂贵的 f32 精排**。QuIVer 的 `search_flat` 是两段式
（BQ2 码导航 → 对 top-`ef` 做 f32 精排），所以误差界的价值 = 剪掉**精排**候选。

### 1.2 六个配置（分离四个变量）

| 配置 | 导航码 | 精排阶段 | 展开规则 | 隔离的变量 |
|---|---|---|---|---|
| **A** | BQ2 2-bit | f32 全量 | 标准 | 当前 QuIVer 基线 |
| **B** | BQ2 2-bit | 5-bit 界剪枝 → f32 | 标准 | **候选剪枝净收益** |
| **C** | 5-bit | 5-bit 界剪枝 → f32 | 标准 | 激进方案（导航也换） |
| **D** | 5-bit | f32 全量 | 标准 | 升级导航码的净成本 |
| **E1** | 5-bit | f32 全量 | 界**计数不剪** | **展开剪枝判别力**（召回 = D） |
| **E2** | 5-bit | f32 全量 | 界**真剪展开** | **展开剪枝代价** |

### 1.3 为什么旋转不破坏对比

5-bit 码建在**旋转后**数据上（§2 实测：无旋转时 ε 在 B≥5 饱和，剪枝恒 0%）。
旋转是正交变换，`⟨Rq_u, Rx_u⟩ = ⟨q_u, x_u⟩`，故旋转码估计的**仍是同一个真值**
（归一化后的内积 = cosine）。**旋转只作用于码，不作用于图** —— 图拓扑仍由未旋转 BQ2 构建，
所以 A/B 与 C/D 共享同一张图，差异纯粹来自码与剪枝。

### 1.4 正确性守卫（四条，全部通过）

| 守卫 | 内容 | 结果 |
|---|---|---|
| **0** | 旋转正交性（内积保持） | `0.714939 vs 0.714940`，相对误差 **5.0e-7** ✅ |
| **1** | 保真度：配置 A@ef=128 必须落在冻结基线 ±1.5pp | **98.07%** vs 97.55%（偏差 **0.52pp**）✅ |
| **2** | 界成立：`\|est − true\| ≤ ε + 1e-3` 抽检 | **0 / 40000 违例** ✅ |
| **3** | 候选剪枝不损召回：B ≥ A、C ≥ D | 全部 **+0.00pp** ✅ 与"可证安全"一致 |
| **4** | E1（界计数不剪）与 D 结果**逐位一致** | 全部 **PASS** ✅ 证明计数器无副作用（否则 V1b 读数不可信） |

> 守卫 0 抓到过一次真实 bug：旋转第 2/4 轮我误把符号翻转限制在 512 长段内
> （正确实现要求翻转作用于**整个 768 缓冲**，只有 FHT 作用于段）。那会让变换不再正交，
> 使 `est`/`ε` 全部指向错误目标量 —— 一个代价极高的静默错误。

## 2. 内核微基准（独立于遍历，最硬的证据）

1M 向量上的单线程测量，200k 次重复：

| 内核 | ns/次 | 相对 BQ2 | 说明 |
|---|---|---|---|
| BQ2 2-bit 距离 | **29.3** | 1.0× | 12 chunk 位运算 |
| **5-bit RaBitQ est** | **435.1** | **14.8×** | 96 组 u64 解包 + 768 MAC |
| **f32 精确内积** | **313.5** | **10.7×** | 768 MAC，可向量化 |

**★ 5-bit 估计量比 f32 精确内积还慢 39%。**

这是 R2 的直接证据：`est` 与 `ε` 都从 5-bit 码算出，所以在做精排决策之前，
已经付出了 1.39× 于"干脆直接做 f32"的代价。而它换来的剪枝率是 **0.6%**（见 §4）。
→ **`(1 + 0.39) × 0.994 ≈ 1.38`，即"界剪枝"把精排阶段的成本抬高了约 38%，而不是降低。**

> ⚠️ 本微基准用标量实现（未手写 SIMD）。真实实现里 f32 会得到 AVX2 加速（约 8×），
> 而 5-bit 解包难以同等向量化 → **真实差距会比 14.8× / 1.39× 更大**，
> 即结论方向不变、程度更严重。

### 3.1 R1：剪枝能力不可迁移（★ 本次最重要的发现）

**精排保留率 99.4–100%** —— 想剪掉 72%，实际只剪掉 **0–0.6%**。

为什么？两次测量的候选集性质完全不同：

| 场景 | 候选集 | 剪枝率 |
|---|---|---|
| ε-scaling §3（10 万原始候选） | 绝大多数候选**离查询很远**，`est` 远低于门槛 | **72.4%** |
| V1（图遍历的 `ef` 个精排候选） | 已是最近的 `ef` 个，`est` 彼此**聚簇**、误差区间互相重叠 | **0–0.6%** |

误差界的判别力来自**远处候选**，而图遍历**已经把远处候选消灭掉了**。
→ 72% 这个数字对图遍历**不可迁移**。这是可移植的结论，不依赖本原型的实现质量。

### 3.2 R2：成本倒挂导致净负收益

| 对比 | ef=128 | 差异 | 原因 |
|---|---|---|---|
| **B vs A** | 3,369 vs 3,463 | **−2.7%** | 剪枝只省了 0%（100% 保留），却为全部 `ef` 个候选付了 5-bit 估计量：`128×435 = 55.7 μs`，而 f32 精排才 `128×313 = 40.1 μs` |
| C vs D | 2,989 vs 3,018 | −1.0% | 同上，且导航也换成 5-bit |

精排阶段成本模型：`A = 40.1 μs`，`B = 55.7 + 0.994×40.1 ≈ 95.6 μs` → **B 的精排阶段是 A 的 2.4×**。
端到端只掉 2.7%，是因为该原型里非内核开销很大（见 §4 限制）。

### 3.3 附带发现：导航码升级的代价

C/D 与 A/B 的召回**几乎相同**（98.15% vs 98.07% @ ef=128），说明 5-bit 码作为导航码并没有带来召回优势
（它只在 §2 的 ε 意义上更"可控"，但图遍历并不需要）。而 D vs A 的 QPS 差（3,018 vs 3,463 = **−13%**）
即升级导航码的纯成本。

> 注意：本原型里 5-bit 导航的惩罚只有 13%，远低于内核比 14.8×。
> 原因是该原型的非内核开销占主导，稀释了内核差异（§4）。**真实实现里这个惩罚只会更大。**

### 3.4 V1b：界驱动的**展开剪枝**（判别力与代价分离）

#### 为什么不能像候选剪枝那样宣称"可证安全"

候选剪枝（`safe_prune`）**可证安全**：它只断言"该候选**自己**不在真 Top-k"。
展开剪枝则**不可证**：图边不蕴含相似度单调性 —— 一个自身得分低的节点 `u`
完全可能有得分高的邻居。Vamana 的 `α` 剪枝只保证邻居"**不远比**自身更远"，
**并不排除邻居更近**。故展开剪枝是**启发式**，必须实测其召回代价。

#### E1/E2 拆分（分离判别力与代价）

| 配置 | 行为 | 作用 |
|---|---|---|
| **D** | 5-bit 导航 + f32 全量，标准终止 | 基线 |
| **E1** | 同 D，但**算出界判据却不跳过** | 纯测**判别力**（召回必须 = D，否则计数器有副作用） |
| **E2** | 同 D，但**真的跳过**被界排除的展开 | 测**召回代价** |

#### 结果

| ef | E1 判别力 | θ − U | ε | **θ − est** | E2 实跳过 | E2 召回 Δ vs D | 导航求值节省 |
|---|---|---|---|---|---|---|---|
| 64 | 0.00% | −0.1046 | 0.0558 | **−0.0487** | 0.00% | +0.00pp | 0.0% |
| 128 | 0.00% | −0.0940 | 0.0558 | **−0.0381** | 0.00% | +0.00pp | 0.0% |
| 256 | 0.01% | −0.0841 | 0.0558 | **−0.0283** | 0.01% | +0.00pp | 0.0% |
| 512 | 0.10% | −0.0751 | 0.0558 | **−0.0193** | 0.10% | +0.00pp | 0.1% |

> 判据为 `U(u) = est_u + ε < θ`（θ = `results` 中第 k 大下界），等价于 `ε < θ − est_u`。
> **`θ − est_u` 在全部 ef 下为负** ⇒ 该不等式对**任何** `ε ≥ 0` 都不成立。

#### 机制：结构性失效，与码精度正交

`frontier` 是"越大越近"的最大堆，`frontier.pop()` 返回的必然是**未展开节点中 `est` 最大者**。
而每个节点在被推入 `frontier` 之前**已经先被推入 `results`**，所以被弹出的 `u` 几乎总在
`results` 内；又因它是未展开者中 `est` 最大者，它按构造就是 **Top-k 的候选者**。
于是 `θ`（第 k 大下界）≤ `L_u` ≤ `est_u`，即 `θ − est_u ≤ 0` —— **判据的失效与 `ε` 无关**。

这也解释了判别力为何随 `ef` **微升**（0.00% → 0.10%）：`ef` 越大搜索越深，
后期才会弹出 `est` 已明显落后的节点；而那些节点**恰好正是标准终止条件
`dcur < worst_in_results` 马上要停下的**，故边际收益可忽略。

另：`E2` 的召回 Δ = **+0.00pp** 并不代表"剪枝不损召回"，而是"**根本没剪**"——
不能误读为正面证据。

#### V1b 结论

**展开剪枝在结构上不可行，且不可行性与量化码的质量无关。**
因此 T1 的"界驱动剪枝"路线**整族关闭**（R1 候选剪枝 + R3 展开剪枝 + R2 成本倒挂）。

## 4. 本实验的限制（必须声明）

1. **绝对 QPS 不可与生产实现对比**：本原型内核为标量（未手写 SIMD），
   且自实现 beam search 未做生产级优化，实测 A@ef=128 = 3,463 MT-QPS
   而冻结基线 `bench_cohere1m` 为 **31,568 MT-QPS（9.1×）**。
   → **只有同一原型内的 A/B/C/D 相对差**有意义。
2. **相对差被稀释（方向保守）**：本原型非内核开销占主导，使内核成本差异被压低。
   在更精简的实现里，B 的额外 5-bit 成本与 D 的导航成本都会**更明显**。
   → 即本报告的负向结论是**保守（低估）**的，不会高估损失。
3. **只测了内存驻留场景**：全部 f32 向量驻留内存。冷/SSD 场景未测（见 §5）。
4. **单机口径**：i9-14900K，**无 AVX-512**（实测）。论文硬件 Zen4 有 AVX-512 VPOPCNTDQ，
   会同时加速 BQ2 与 f32 两条路径；对 R2 的**方向**无影响（f32 同样受益于更宽的 SIMD）。
5. **重编译会带来 ~0.05pp 的召回抖动**：`-C target-cpu=native` 下浮点求和顺序随内联/向量化变化，
   同一配置（A@ef=128）在三次重编译中为 **98.07 / 98.08 / 98.10%**。
   不影响任何结论（所有守卫余量远大于此），但**冻结基线数字时须同时记录二进制指纹**。

## 5. 唯一可能成立的转向：冷层场景

R1（剪枝能力）与 R2（成本倒挂）都建立在 **f32 向量内存驻留**的前提上。若 f32 层在 SSD：

- **R2 可能反转**：一次 SSD 随机读的延迟是 `μs` 级，远高于 435 ns 的 5-bit 估计。
  此时"先算界、避免一次盘读"是明显划算的。
- **R1 需要重新表述**：剪枝的对象不再是"近邻候选"，而是"**是否需要为这个候选发起一次盘 I/O**"。
  即使近邻候选剪不掉，只要能把**远处候选**挡在 I/O 之前，价值就成立 ——
  而这正是 §3 里 72% 那个数字所度量的场景形式。

**但必须诚实指出**：QuIVer 当前的两段式是 `BQ2 预筛 → 从 cold file 读 f32 精排`。
第一段（BQ2 预筛）已经承担了"挡掉远处候选"的职责，且成本仅 29.3 ns。
所以第二道防线（5-bit 界）要证明的是：**它能在 BQ2 预筛之外再挡掉多少本会触发盘读的候选**。
这需要 `bench_ssd_cold_hot` 类型的实验，且**必须先解决摸底报告 R2**
（`QuIVer::load_bytes` 名为 mmap 实为逐数组 `collect()`，会让"冷"的定义失真）。

## 6. T1 的最终状态

经四轮修正，T1 的形态收敛如下（每一步都由实测推动）：

| 轮次 | 假设 | 裁定 |
|---|---|---|
| 1（摸底） | RaBitQ 量化码替换 BQ2 提升精度 | ✗ 等比特下旋转为负增益（−2.15/−2.95pp） |
| 2（ε-scaling） | 用误差界做可证剪枝，门槛 5 bit/维 | △ 在**穷举候选集**上成立（72%），但门槛 2.5× 码长 |
| 3（V1） | 把**候选剪枝**搬进图遍历的精排阶段 | ✗ **R1 剪枝能力塌到 0.6% + R2 成本倒挂 39%** |
| **4（V1b）** | 改用**展开剪枝**绕开 R1/R2 | ✗ **R3 结构性失效：θ−est < 0 ⇒ 换任何码都不行** |
| **5（剩余可能）** | **只可能在 f32 非驻留（冷层/SSD）时成立** | **待验证，且前置依赖摸底 R2 修复** |

**当前裁定：T1 在"内存驻留 + 图遍历"下应停止投入。**
若要继续，唯一合法路径是**冷层 I/O 避免**，且必须先修好 `load_bytes` 的伪 mmap 问题，
否则冷热实验的结论不可信。

**建议把资源转向 T2（PiPNN 图构建）与 T3**：`l1-followup.md` §1.3/§1.4 已显示
索引结构的改动收益量级（相对 HNSW 4–5×、相对 IVF+RaBitQ 15–35×）远大于量化层（实测为负）。
