# Submission package — contents, and the three things only the authors can fill in

Generated by `.venv/Scripts/python.exe scripts/paper/build_submission.py` from the Markdown sections
(`docs/paper/section-0-abstract.md` … `section-12-references.md` are the source of truth; do **not** edit
`paper.md` by hand — it is rebuilt on every run).

| File | What it is |
|---|---|
| `quiver-independent-eval.tex` | single-document LaTeX, self-contained (the custom preamble is inlined); this is the arXiv source |
| `quiver-independent-eval.pdf` | compiled PDF (33 pages, Letter) |
| `paper.md` | the assembled Markdown the LaTeX was generated from |
| `abstract-short.txt` | 1,808-character abstract for the arXiv **metadata** field (limit ≈ 1,920) |
| `figures/*.pdf` | the six figures, converted from `docs/paper/figures/*.svg` |

## 1. Fill in before submitting (cannot be automated)

1. **Author block** — in `scripts/paper/build_submission.py`, replace `AUTHOR_PLACEHOLDER`
   (`AUTHOR NAMES, AFFILIATION, E-MAIL [TO BE FILLED IN BY THE AUTHORS]`) with the real names,
   affiliation(s), e-mail(s) and ORCIDs, then re-run the build. The placeholder is deliberately glaring in
   the PDF so it cannot ship unnoticed.
2. **Licence** — arXiv asks for a licence for the **paper** (CC-BY-4.0 is the usual choice for a technical
   report; `arXiv.org perpetual, non-exclusive` is the conservative option). The **code** stays Apache-2.0
   under the repository `LICENSE`.
3. **Final read-through** of `quiver-independent-eval.pdf` (33 pages) — especially §5.6(b), §10 and §12.

## 2. arXiv submission (suggested: primary cs.DB, cross-list cs.IR)

1. Log in / register at arxiv.org. **Check endorsement early**: a first submission to `cs.DB` may require an
   endorsement code from someone with submission rights in that category — this can take days, so start it
   first.
2. `Start new submission` → licence → category **cs.DB**, cross-list **cs.IR**.
3. Upload `quiver-independent-eval.tex` **and** the `figures/` directory (keep the relative paths
   `figures/figN-*.pdf`). `paper.md`, `abstract-short.txt` and this README are not needed by arXiv.
4. Paste `abstract-short.txt` into the metadata **Abstract** box (the PDF's own abstract is longer and stays
   in the paper).
5. Let arXiv compile, inspect the generated PDF, then submit. (Title/author metadata are taken from the
   `.tex`, so step 1 above must be done first.)

## 3. Build notes (why the pipeline does what it does)

* Figures are converted **SVG → PDF** with PyMuPDF because XeTeX cannot read SVG.
* Figure numbering is **manual** (`**Figure N.**` in the captions, `\captionsetup[figure]{labelformat=empty}`)
  so the numbers match the `figN-*` file names and the README/§11 references; re-ordering figures therefore
  means editing captions in the section files.
* Unicode mathematics (`≤ ≥ ≈ ⇒ Δ μ …`) is mapped to LaTeX math at build time; **code blocks and headings are
  ASCII-downgraded** because Latin Modern's monospace font lacks those glyphs and PDF bookmarks forbid math.
* `--toc` but **no** `--number-sections`: the section headings already carry their own numbers, and the text's
  `§11.3a`-style cross-references must stay valid.
