## 默认查询路径

当前数据库普通向量查询采用：**原 BQ 快速构图 → 签名多样性保护与入口可达性修复 → 无训练 SM-L2 导航 → 有界原始向量余弦精排 → 按需读取 Payload**。近邻选择沿用原 QuIVer 的 BQ 路径；最终剪枝出现同签名近邻挤占时，利用既有容量保留其他签名的候选。随后仅给不可达区域补边。没有签名碰撞且原本全可达的图，其拓扑保持不变。

| 环节 | 当前行为 |
|---|---|
| 构图 | 使用低位 BQ 编码和原批量并行图构建路径；独立 SM 研究构图器不等于默认生产构图器 |
| 表示 | 两个位平面保存符号与强弱分组，并保存每向量弱幅值、幅值差与重建范数等紧凑元数据 |
| 导航 | 使用重建向量的平方 L2 评分，结合位计数和幅值运算；不能再概括成纯 Hamming 寻路 |
| 精排 | 默认查询仍按原始向量余弦相似度返回分数，SM-L2 名称不表示切换了用户查询的度量 |
| 训练 | 默认路径无需查询样本校正、锚点拟合、码本或旋转训练；每向量幅值由该向量自身计算 |
| 执行 | 768 维保留专用实现，其他合法维度使用通用实现；运行时选择可用 SIMD，保留标量和尾部处理 |
| 维度 | 支持 `1..=3072`，包括非 64 倍数；更高维数据库保持精确 BruteForce 路由 |

概念上，每维重建值为 `符号 × (弱幅值 + 强位 × 幅值差)`；SM-L2 比较重建向量之间的平方距离。它不等同于仅比较两个位串的 Hamming 距离，也不保证近似候选与精确余弦 Top-K 完全相同。

底层 `QuIVerSearchConfig` 的有效候选宽度至少覆盖 `top_k`，并受节点数限制。未显式指定 `rerank_limit` 时默认预算为 64，实际预算按 `min(有效候选宽度, max(top_k, 指定预算或64))` 计算。上层管线显式传入的预算继续生效；过滤拒绝和墓碑不占成功精排名额。低 `ef` 会收紧有效精排预算，普通默认查询不因此静默回退旧 BQ。

## 默认、显式与兼容模式

| 模式 | 启用与度量 | 边界 |
|---|---|---|
| 默认无训练 SM-L2 | 数据库构图和加载后自动准备；最终余弦精排 | Python、Node.js 和 Rust 普通查询共用 Core，无需手动调用启用函数 |
| 显式校正 SM | Rust 显式安装带校正系数和锚点的模型 | 属于独立研究/消融配置；不能将其训练成本或结果归给无训练默认模式 |
| 显式原生 L2 | Rust `enable_quiver_sm_native_l2()`；保留原始幅值与合法零向量，返回负平方欧氏距离 | 不是数据库全局度量开关；不等同于普通余弦查询，也不保证欧氏数据上的高召回 |
| 自定义导航 | 使用 `NavigationScorer` 的 TSNG 等入口 | 保留其显式评分协议，不能宣称全部导航入口已统一改用 SM-L2 |
| 独立旧索引兼容 | 仅从字节加载、尚未绑定原始向量的 `QuIVer` 对象 | 可保留旧 BQ 路径；数据库加载流程会补齐默认 SM 状态 |

显式覆盖在图或向量变化后失效，普通查询恢复默认 SM-L2。显式校正锚点被过滤屏蔽时，可以采用无锚点默认 SM；查询出错不得通过切换为另一种精排度量伪装成功。

## 增量维护、重载与内存

- 构图时准备默认 SM 状态，插入时追加新节点的紧凑行。墓碑可以参与导航，但不进入结果，也不能将已复用 slot 中的新向量当作旧节点向量。
- 构图和加载时派生从当前入口覆盖全图的导航树，每节点保存一个 `u32` 父节点，计入索引热内存。增量剪枝保留树边，入口升层时连接旧树；补边使用既有邻接表容量，不自动扩大存储步长。必要时出度可高于常规 `m0`，但不超过原有 `2*m0` 容量；无碰撞且全可达的正常图不额外加环。
- 入口全可达保证的是图拓扑可以遍历全库，不代表有限 `ef`、精排预算下的 Recall@K 必然为 100%；近重复、量化签名碰撞和低内在维度数据仍需独立验证召回和性能。
- 旧索引通过重新构建应用本次修复，不提供加载时补边或独立的旧图修复入口。加载发现入口不可达节点时返回需要重建的错误，数据库沿用现有缺失/无效索引处理流程：通常在首次查询时重建，严格索引策略则返回错误。
- `.quiver` 磁盘格式仍为 v1。重建后的索引加载时保持邻接表逐边不变，仅派生运行期导航树。数据库从实际向量池按 slot 流式恢复默认 SM 状态；这会读取冷向量，不能称为“零开销恢复”。拓扑全可达与有限宽度下的召回质量必须分别验证。
- 默认准备过程不保留第二份全库 FP32 向量。显式模式的安装路径可能使用全量临时 FP32 缓冲，安装峰值与稳定驻留应分别计量；显式原生 L2 的度量选择不由旧图文件自动恢复。
- 热内存包括仍保留的原 BQ、默认/显式 SM 状态、图、ID/slot 映射、派生缓存和每线程工作区。不得只计新增 SM 位码，或将历史“低于 1.3 GB”“内存减半”直接用于当前版本。
- 原始向量及 Payload 冷层、映射文件、RSS/PSS、OS PageCache 和安装临时峰值分别报告。SM 拥有内存进入索引及内核预算，不代表预算覆盖整个进程或 OS PageCache。

## ICDE 实验与历史结果的边界

当前主评估范围为 21 项：19 项余弦任务，加 SIFT/GIST 两项原生 L2 边界对照。维度支持不等于任意数据分布或度量上的性能保证。SIFT/GIST 的原生 L2 结果不能与旧稿归一化后按余弦重算 GT 的结果直接替换或混比。

早期 19 项实验中有 43 个低 `ef` 位置实际走过旧 BQ 回退，必须保留其真实方法标签。后续 SM 补测须使用独立原始记录、源码/二进制哈希及覆盖清单；旧调参若使用 BQ，不能事后改称 SM-L2 调参，也不能按新评估成绩重新挑参数。当前源码已经修复低宽度预算和默认生命周期，不会追溯改变旧实验身份。

论文性能结论必须绑定同一份数据、图、参数、路由和实现版本；记录：

1. 输入、GT、查询划分和 ID 映射的选择规则与哈希，自匹配和并列分数处理规则。
2. 构图参数、构建次数、调参集合、冻结后的查询宽度、精排预算及实际启用的评分模式。
3. 输入读取、构图、SM 准备、保存、加载和重载恢复的计时边界，不能把未分离的开销填为零。
4. 分开测量的吞吐与逐查询延迟、独立轮次、P50/P95/P99、线程数和跨线程结果一致性。
5. 热组件、冷向量依赖、工作区、驻留和临时峰值；原 BQ 未释放时仍计入。

旧预印本的 12 库 Recall/QPS、旧消融配置及表号属于历史版本。当前 ICDE 结论以对应冻结记录和独立复核为准；本页不将历史数字或局部 200K 消融推广为当前版本的跨库保证。
