# TriviumDB 0.9.0-beta.1

本次 Beta 提供嵌入式多实例资源管理、受控关闭与目录快照。Rust、Python 和 Node.js 共享内核语义，并同步提供配置、诊断、错误字段和类型声明。

## 版本与安装

| 制品 | 版本 |
| --- | --- |
| Rust crate、CLI、Server、npm | `0.9.0-beta.1` |
| Python / PyPI | `0.9.0b1` |
| Git 标签 | `v0.9.0-beta.1` |

```bash
pip install "triviumdb==0.9.0b1"
npm install triviumdb@0.9.0-beta.1
cargo add triviumdb@0.9.0-beta.1
```

npm 使用 `beta` 发布通道；后续 Beta 按序号递增。

## 共享资源运行时

- 多个数据库通过 `ResourceRuntime` 共享声明配额、临时工作区、计算线程和任务名额。
- 总预算内保护维护工作区，前台与维护根任务单独计数。有限总预算下，每个数据库声明非零实例配额。
- 数据库打开前登记配额，调整失败保留原值；打开失败和成功关闭时归还登记。
- 扫描、构图、TQL 与后台维护使用运行时工作池。周期维护共享进程计时线程，已排空的关闭任务优先调度。

内存准入按声明配额与已接入工作区预留核算。进程容量规划同时采集 mmap 驻留、页缓存、线程栈、语言运行时与 Hook 开销。

## 实例与维护诊断

- `runtime.stats()` / `db.resource_stats()` 提供共享账本、线程和任务统计，以及前台/维护可用内存和前台任务余额。
- `db.instance_stats()` 提供本库路径、配置配额、内存采样、活动操作数、关闭状态和周期维护状态。写锁占用时内存采样返回 `None` / `null`，诊断可在后续轮询中重试。
- 维护状态记录成功、失败、延期次数，并区分排空等待、资源准入延期、数据库忙与执行故障。
- Python `ResourceBudgetError` 和 Node `QueueFull` 错误携带 `resource`、`requested`、`used`、`limit`。Node `searchBatch()` 的 Promise 拒绝提供相同字段。

## 受控关闭

- `request_shutdown()` 停止新操作并登记排空与持久化任务。
- `close_timeout()` 完成时返回 `true`，等待超时返回 `false`，关闭失败返回错误。
- `shutdown_status()` 报告 `open/draining/flushing/failed/closed` 阶段、活动操作数、最近结构化故障与关闭维护状态。
- 等待超时后，任务继续持有数据、配额和文件锁。失败原因由状态与原始错误返回，调用方可按协议重试。
- Python 关闭等待释放 GIL；Node 提供同步等待及零等待轮询入口供宿主管理事件循环。

## 目录快照与恢复

- `create_snapshot()` 在源库写锁下完成 checkpoint，捕获完整代际到新目录。
- `verify_snapshot()` 检查 manifest、文件集合、长度、CRC 和主文件头；`restore_snapshot()` 校验后恢复到新目录。
- 制品通过有界复制、逐文件同步、暂存目录校验、目录 rename 和父目录同步发布。发布后同步失败时保留完整目标，并返回发布状态不确定错误。
- 恢复目录中的数据库名为 `database.tdb`，宿主按 dtype、维度、预算及访问模式打开。

## 升级说明

- Rust `set_memory_limit(bytes)` 返回 `Result<()>`，调用方处理配额调整结果。Python/Node 保留相应的 MiB 配置接口。
- `.tdb` 主文件格式继续使用 v9，目录快照复用现有 generation manifest 格式。QuIVer 构图、导航和评分算法保持上一版本实现。
- NPM 发布使用仓库中已测试的加载器与多平台构建产物，包含 `dispose` / `Symbol.dispose` 生命周期封装。
