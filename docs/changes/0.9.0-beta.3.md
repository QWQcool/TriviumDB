# TriviumDB 0.9.0-beta.3

本次 Beta 完善事务、恢复、索引一致性与数值边界，并统一原生三模 TQL 在 Cascades 规划下的值、绑定和返回语义。Rust、Python、Node.js 与 CLI 共享这些内核行为。

## 版本与安装

| 制品 | 版本 |
| --- | --- |
| Rust crate、CLI、Server 源码、npm | `0.9.0-beta.3` |
| Python / PyPI | `0.9.0b3` |
| Git 标签 | `v0.9.0-beta.3` |

```bash
pip install "triviumdb==0.9.0b3"
npm install triviumdb@0.9.0-beta.3
cargo add triviumdb@0.9.0-beta.3
```

npm 使用 `beta` 发布通道，GitHub Release 标记为预发布。Server 与 WebUI 沿用 nightly 开发通道。

## 事务、写入与 WAL 恢复

- 事务按操作顺序维护节点存在状态。删除后可重建、更新或再次删除同一 ID；重建后的重复插入在写入 WAL 前整批拒绝，保留节点、索引、ID 分配状态与 WAL。
- 唯一索引按事务最终状态维护键所有权。节点可临时使用其他节点的复合键后再次改键或删除；最终投影保留其他节点的所有权，允许的键交换可原子提交。
- 事务提交前完成数值、JSON、唯一性与预算检查，并准备已校验的应用数据。应用异常向调用方传播并隔离当前实例及共享查询；重开按完整已提交 WAL 恢复。RAII 恢复 QuIVer 同步暂停状态，事务编号使用检查耗尽的进程内单调计数。
- WAL 追加、flush 或同步失败后隔离 writer，后续写入、分组提交及检查点返回 `WalClosed`。释放句柄并重开后核对实际恢复状态；失败操作的持久化结果取决于实际日志，应用可按业务标识处理重试。
- 恢复在帧与 CRC 校验后检查 JSON、向量维度、有限值和 ID 边界。语义非法记录返回结构化损坏错误，并保留原 WAL 与检查点。未提交事务和截断尾部按提交边界处理。
- 普通 CRUD、事务和边元数据采用读取可解码的 JSON 深度边界。Payload 替换、事务更新与 `$set` 增长在 WAL 前执行预算准入；`$inc` 保持整数精度，并原子拒绝溢出、非法类型及非有限结果。
- 快照 manifest 的 generation_id 采用统一路径组件校验，拒绝父级或绝对路径及非法名称，目录存储与底层写入入口使用同一规则。

## 属性索引、图索引与持久化格式

- 删除 Hash 唯一索引同步移除对应唯一约束，后续写入与重开的约束定义一致。
- Ordered 排序和复合前缀/范围路径按实际字段覆盖选择候选；缺失字段、容器、布尔和 Null 保留完整查询结果。范围候选在 LIMIT/OFFSET 前约束数值或字符串类型，再执行完整谓词。
- 复合唯一键精确保留 `i64/u64/f64` 类型与值。超过 2^53 的相邻整数保持可区分；有序范围与排序在精度边界采用精确比较或扫描。
- TQL 数值等值候选合并精确等价的整数与浮点键，例如 `1` 和 `1.0`；Hash/Bitmap 的文档值键继续保留各自的 JSON 类型语义。
- Hash、Ordered、Bitmap、Composite、N-gram 与唯一索引创建统一执行解析及构建峰值准入，并独立准备候选。预算拒绝、非法字段或唯一性失败保留已有定义、缓存和 WAL，可调整配额后重试。
- `.pidx` 使用 v7，校验实际 Payload 字节；`.gidx` 使用 v3，校验主文件事实。旧属性索引按定义在内存重建，旧图索引通过主文件读取；只读打开保持物理零写，可写检查点发布当前格式。
- 只读图按实际入边数统计入度，多标签平行边的分数、排序及完整性检查与可写模式一致。删除最后一条入边同步移除零入度项。
- 图写入在 WAL 前检查标签的 65,535 UTF-8 字节上限。堆计量包含标签、Metadata、邻接容量和相关反向、标签、统计及缓存结构，写入与更新增量维护预算。

## TQL 返回、匹配写入与完整数值域

- MATCH、FIND、WITH 与单跳具名边共用表达式、分组、聚合、DISTINCT、别名排序与分页。计算表达式和节点 ID 形成完整分组键；COUNT(expr) 按实际非 Null 值计数，聚合 DISTINCT 按对应值去重。
- 返回列独立于输入绑定。省略 AS 的聚合使用表达式列名；同名返回别名保留其他列引用的源绑定。字面量使用规范文本作为默认列名，`RETURN 1, 2` 返回两列，重复列名明确报错。
- WITH 在执行点保存每行的值与实体身份；所有右值读取进入阶段时的作用域后同时赋值。连续扩展保留源节点、标量和 JSON 内容，多源汇合保留不同投影环境的逻辑行。投影内存计入实例与共享工作区，完成、拒绝或异常展开归还临时配额。
- 算术、COALESCE 和空值表达式递归检查全部变量。标量重命名保持标量类型，后续 WITH 明确确定保留列。ORDER BY 别名保留实体、路径和容器类型，并支持实体及对象字段排序。
- 单跳边变量在 WHERE、RETURN、空值判断和聚合中保留完整绑定，支持匿名端点。OPTIONAL MATCH 先验证起点，再按模式与 WHERE 匹配边；无合格后缀时为有效起点补齐 Null。重复节点变量约束同一实体，自环在单次双向匹配中计数一次。
- MATCH 内联 `id` 与节点 `.id` 使用完整无符号结构 ID；FIND/MATCHES 文档条件读取 Payload 字段。结构 ID 与 Payload 的 `id` 索引分别按其事实域筛选和排序。
- 多字段 SET 按节点累计赋值并原子替换，重复字段采用最后一次赋值。MATCH … CREATE 按每条完整匹配创建，零匹配产生零次创建，每行使用独立的新节点作用域。
- TQL 字面量、参数、比较、投影、排序和聚合覆盖 `i64::MIN..=u64::MAX`。整数加减乘及 SUM 保持整数，整数溢出返回 Null；MIN/MAX 保留选中数值。浮点相等使用实际值，除法仅将正负零视为零分母，有限的小分母正常计算。
- SEARCH、RANK、RESIDUAL 与 SET VECTOR 按目标 dtype 转换数值。u64 向量保留完整位模式，负数、小数和超范围值明确拒绝；f32/f16 校验转换后的有限范围。Prepared SEARCH 保留整数参数，检查缺参、额外参数、非有限值和非法槽位；默认参数列名在绑定前确定。

## SDK 数值与 Payload 一致性

- Python 直接写入和事务按 u64 类型提取向量，保持完整整数位模式。Payload 整数覆盖完整 i64/u64，元组转为数组；非法对象、非有限值和非字符串字典键明确报错。输出保留精确 Python int。
- Node 数值 ID 在转换前检查安全整数，数量参数检查有限性、整数性与范围。数字 ID 输出遵守相同安全范围；TQL 的大整数标量及列表、对象内的对应整数采用十进制字符串，节点和路径 ID 保持完整字符串。
- Rust/Python 节点 ID 范围为 `1..=u64::MAX-1`；保留值和分配耗尽在 WAL 前拒绝。Node 自动插入、批量、事务、TQL CREATE 和迁移在持久化前检查可返回 ID。
- 数组、对象、节点、边与路径保留各自的表达式类型；COALESCE、IS NULL、COUNT、分组和去重处理实际值。Rust 对象结果使用 `TqlValue::Object`，Python/Node 返回原生对象。

## 检索确定性与计量

- BruteForce 使用分片有界 Top-K 堆，按分数降序、外部 NodeId 升序合并。QuIVer 默认 SM 与公开 BQ 路径在候选精排和最终同分结果中使用外部 NodeId；无效公开索引查询遵守其 Vec 返回契约，冷向量视图检查维度与有限值。
- QuIVer、Payload、图、属性 posting 和文本的热内存通过增量计数或容量计量读取，写入准入保持计量成本稳定。完整图统计用于诊断，属性统计的字段与类型顺序跨加载模式保持一致。
- 实验追加构图入口顺序执行反向剪枝，保留追加及邻居选择语义。实例预算描述受管理堆与工作区，RSS 与 OS 页缓存由对应诊断指标记录。

## Rust API 与文件组迁移

- 查询字面量和 Prepared 值增加 `UInt(u64)`，结果增加 `TqlValue::UInt` 与 `TqlValue::Object`；穷尽匹配这些枚举的调用方补充对应分支。
- `MutationAction::SetVector.vector`、`QueryEntry::Search.vector`、`RankClause.vector` 与 `ResidualStage.vector` 使用 `Vec<serde_json::Number>`。`VectorType::from_json_number()` 提供默认类型转换入口，自定义类型可覆盖。`pipeline::lower_search_entry()` 返回 `Result`，调用方传播转换错误。
- 物理行新增 `NodeRow.bindings` 与 `BindingValue`；通过 `NodeRow::new()` 构造空绑定。Rust 节点结果适配按保存的身份返回源节点别名。
- 升级时关闭现有实例，保存完整文件组或目录快照，再由新版本打开。旧 sidecar 的加载和当前格式发布遵循上述规则；旧版本回退使用对应版本的原始备份。完整备份与恢复步骤见[生命周期与快照](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0-beta.3/docs/lifecycle-snapshots.md)。

# English release notes

This beta strengthens transactions, recovery, index consistency and numeric boundaries, and aligns values, bindings and return semantics across native tri-model TQL queries planned by Cascades. Rust, Python, Node.js and the CLI share these kernel behaviors.

## Versions and installation

Rust, CLI, Server source and npm use `0.9.0-beta.3`; Python/PyPI uses `0.9.0b3`; the Git tag is `v0.9.0-beta.3`. The installation commands above select these exact versions. npm uses the `beta` channel and GitHub marks the release as a prerelease. Server and WebUI continue on the nightly development channel.

## Transactions, writes and WAL recovery

- Transaction preflight tracks node existence in operation order. An ID can be deleted, recreated, updated or deleted again. A duplicate insertion after recreation rejects the complete transaction before WAL writes, preserving facts, indexes, allocation state and the log.
- Unique indexes maintain ownership from the final transaction state. A node may temporarily use another node's composite key before changing again or being deleted. Final projection preserves the other owner and supports valid atomic key swaps.
- Commit preflight validates numbers, JSON, uniqueness and memory growth, then prepares validated application data. Unexpected application failures propagate and isolate the instance and shared queries; reopening replays the complete committed WAL. RAII restores paused QuIVer synchronization, and transaction IDs use a checked process-local monotonic counter.
- WAL append, flush or sync failure quarantines the writer. Subsequent writes, group commits and checkpoints return `WalClosed`. Releasing and reopening the handle reconciles actual persisted state; applications can use business identifiers when retrying an operation whose durable outcome depends on the log.
- Recovery validates semantic JSON, vector dimensions, finite values and ID bounds after frame and CRC checks. Invalid records return structured corruption errors and preserve the original WAL and checkpoint. Uncommitted transactions and truncated tails follow commit boundaries.
- Ordinary CRUD, transactions and edge metadata share the reader's JSON depth boundary. Payload replacement, transaction updates and `$set` growth are admitted before WAL writes. `$inc` preserves integer precision and atomically rejects overflow, invalid types and non-finite results.
- Snapshot manifest generation IDs share path-component validation, rejecting parent or absolute paths and invalid names at both the directory-store and lower-level writer interfaces.

## Property indexes, graphs and persisted formats

- Dropping a unique Hash index removes its matching constraint definition, keeping later writes and reopening consistent.
- Ordered sorting and composite prefix/range paths select candidates according to actual field coverage, retaining missing fields, containers, booleans and nulls. Typed range candidates are selected before LIMIT/OFFSET and then checked by the complete predicate.
- Composite unique keys preserve exact i64/u64/f64 types and values. Adjacent integers above 2^53 remain distinct. Ordered ranges and sorting use exact comparisons or scans at precision boundaries.
- TQL equality candidates union exactly equivalent integer and floating keys, including `1` and `1.0`. Hash/Bitmap document keys retain their JSON type semantics.
- Hash, Ordered, Bitmap, Composite, N-gram and unique index creation share parsing/build peak admission and isolated candidate preparation. Budget rejection, invalid fields and uniqueness failures preserve existing definitions, caches and the WAL, allowing retries after quota adjustment.
- Property sidecars use `.pidx` v7 and validate actual Payload bytes. Graph sidecars use `.gidx` v3 and validate main-file facts. Legacy property definitions rebuild in memory, and legacy graph access reads the main file. Read-only opening preserves physical files; writable checkpoints publish current formats.
- Read-only graphs count actual incoming edges, preserving scoring, ordering and integrity checks for parallel labels. Removing the final incoming edge removes its zero-degree entry.
- Graph writes validate the 65,535 UTF-8-byte label limit before the WAL. Heap accounting includes labels, metadata, adjacency capacity, reverse/label indexes, statistics and caches, with incremental updates for admission.

## TQL returns, matched mutations and numeric domains

- MATCH, FIND, WITH and named single-hop edges share expression evaluation, grouping, aggregates, DISTINCT, alias ordering and pagination. Computed expressions and node IDs form complete group keys. COUNT(expr) counts evaluated non-null values, and aggregate DISTINCT deduplicates the corresponding values.
- Return columns are separate from input bindings. Unaliased aggregates expose expression names, and return aliases preserve other columns' source references. Literals use normalized default column names: `RETURN 1, 2` returns two columns, while duplicate names fail explicitly.
- WITH captures each row's values and entity identities at its execution point. All right-hand sides read the incoming scope before simultaneous assignment. Subsequent expansions retain source nodes, scalar values and JSON contents; converging sources keep distinct projection environments as logical rows. Snapshot memory counts toward instance and shared workspace admission, and reservations are released on completion, rejection or unwinding.
- Scope validation recursively checks every variable in arithmetic, COALESCE and null expressions. Renaming preserves scalar types, and subsequent WITH clauses select retained columns explicitly. ORDER BY aliases preserve entity, path and container types and support entity/object field ordering.
- Named single-hop edges retain bindings in WHERE, RETURN, null checks and aggregates, including anonymous endpoints. OPTIONAL MATCH validates starts before matching the pattern and WHERE; eligible starts without a matching suffix receive null columns. Repeated node variables constrain identity, and a self-loop counts once in a bidirectional binding.
- Inline MATCH `id` conditions and node `.id` properties use complete unsigned structural IDs. FIND/MATCHES document conditions read Payload fields. Structural IDs and Payload `id` indexes use their respective domains for filtering and ordering.
- Multi-field SET accumulates assignments per node and atomically replaces the payload, with the last assignment winning for repeated fields. MATCH … CREATE processes every complete match in a separate new-node scope; zero matches create zero nodes.
- TQL literals, parameters, comparisons, projection, sorting and aggregation cover `i64::MIN..=u64::MAX`. Integer addition, subtraction, multiplication and SUM preserve integers; integer overflow returns Null. MIN/MAX retain selected values. Floating equality compares actual values, and division treats only signed zero as a zero denominator, accepting finite small divisors.
- SEARCH, RANK, RESIDUAL and SET VECTOR convert numbers for the target dtype. u64 vectors retain full bit patterns and reject negative, fractional or out-of-range components; f32/f16 validate their converted finite ranges. Prepared SEARCH preserves integer parameters and checks missing/extra parameters, non-finite values and invalid slots. Default parameter column names are fixed before binding.

## SDK numbers and Payload conversion

- Python direct writes and transactions extract u64 vectors exactly. Payload conversion preserves the complete i64/u64 domain and converts tuples to arrays. Invalid objects, non-finite values and non-string dictionary keys fail explicitly. Outputs preserve exact Python integers.
- Node validates safe numeric IDs and checks quantity arguments for finite, integral values within range before conversion. Numeric ID outputs follow the same safe domain. TQL returns oversized integer scalars and corresponding integers inside lists/objects as decimal strings, with complete string IDs for nodes and paths.
- Rust/Python node IDs use `1..=u64::MAX-1`; reserved values and exhausted allocation fail before the WAL. Node automatic, batch, transaction, TQL CREATE and migration operations validate returnable IDs before persistence.
- Arrays, objects, nodes, edges and paths retain their expression types. COALESCE, IS NULL, COUNT, grouping and deduplication evaluate actual values. Rust uses `TqlValue::Object`; Python and Node return native objects.

## Deterministic retrieval and accounting

- BruteForce uses bounded partition Top-K heaps and merges by descending score and ascending external NodeId. Default QuIVer SM and public BQ paths use external NodeId tie-breaking during rerank admission and final truncation. Invalid public index queries follow their Vec-return contract; cold vector views validate dimensions and finite values.
- QuIVer, Payload, graph, property posting and text hot-memory estimates use incremental counters or capacities, keeping admission accounting cost stable. Full graph statistics serve diagnostics, and property statistics retain field/type ordering across load modes.
- The experimental append builder performs reverse pruning sequentially while preserving append and neighbor-selection behavior. Instance budgets account for managed heap and workspaces; RSS and OS page-cache behavior are recorded by their diagnostic metrics.

## Rust API and file-group migration

- Query literals and prepared values add `UInt(u64)`, and results add `TqlValue::UInt` and `TqlValue::Object`. Exhaustive enum matches need the corresponding branches.
- `MutationAction::SetVector.vector`, `QueryEntry::Search.vector`, `RankClause.vector` and `ResidualStage.vector` use `Vec<serde_json::Number>`. `VectorType::from_json_number()` provides a default conversion entry point that custom types may override. `pipeline::lower_search_entry()` returns `Result`, allowing conversion errors to propagate.
- Physical rows add `NodeRow.bindings` and `BindingValue`; `NodeRow::new()` initializes empty bindings. The Rust node-result adapter resolves saved source identities.
- Close existing instances, preserve the complete file group or directory snapshot, and open it with the new version. Legacy-sidecar loading and current-format publication follow the rules above. Use the corresponding original backup when returning to an earlier version. See the versioned [lifecycle and snapshot guide](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0-beta.3/docs/lifecycle-snapshots.md).

## Validation scope

Local Windows validation covers the Rust workspace, test-hooks interleavings, differential queries, I/O/power-loss faults, transaction guards, sector tearing, and rebuilt/installed Node and Python packages with lifecycle, typing and stub checks. Fixed language contracts assert complete results, numeric values, bindings and ordering. Persistence cases verify the WAL, reopened facts and physical read-only behavior.

Cross-platform, ASan, TSan, Miri, fuzz and published artifacts are recorded by their respective CI/CD jobs; Server follows its independent nightly workflow. See [testing](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0-beta.3/docs/testing.md) and the [API reference](https://github.com/YoKONCy/TriviumDB/blob/v0.9.0-beta.3/docs/api-reference.md) for commands and public contracts.
