# 768 维三引擎重跑：独立审阅

**结论：采集完整，但发布审阅不通过。** 新批次中 TriviumDB 的 4 个 ef 查询点超过预先固定的样本 CV 上限；hnswlib 和 FAISS-HNSW 的组内检查通过。本次没有自动重试；之前 v3 批次的三次失败全部保留。不存在可用于宣称“全部通过”的新三引擎比较，也不进入 X 终稿或出图。

本批记录：[预注册](preregistration.json)、[汇总](summary.json)、[各组决定](decisions.jsonl)；上一批：[完整审阅](../REVIEW-20261106.md)与 [v3 选择记录](../replay-full-v3-20261105/selection.json)。本批是在既有失败后额外进行的一次用户授权采集；在多个批次中根据通过与否选样会引入选择偏差，所有尝试均须披露。

## 已预注册的采集和实际结果

- 三引擎分别独立建图 3 次，每图每个 ef 查询 1 个完整 20K 平铺查询批次；线程 16，M=32、ef_construction=128，cosine R@10=90%，按召回轴线性插值。20K 是平铺条目，并非 20K 独立查询。
- 门槛：每个 ef 以样本标准差（n−1）计算 QPS CV，须不高于 8%；构建时间以 `(max−min)/median` 计算离散度，须不高于 10%；每个独立图及中位曲线须达到目标召回且插值跨度不大于 0.05。

| 引擎 | 三次独立构建 | 建图离散度 | 查询波动门槛 | 本组判定 |
|---|---:|---:|---|---|
| TriviumDB | 3 | 0.873% | ef 10：11.113%；ef 15：13.340%；ef 80：8.851%；ef 120：9.990%，均超过 8% | 不通过 |
| hnswlib | 3 | 0.751% | 全部受检档位通过 | 通过 |
| FAISS-HNSW | 3 | 2.262% | 全部受检档位通过 | 通过 |

三引擎各图和中位曲线的目标召回插值均由独立审阅者复算一致；达到召回不等于稳定性门槛通过。上表 CV 是审阅诊断值，不是 X 文案数字白名单。

## 输入、监督及结果的核验范围

- 九轮均保存 CPU/内存入场检查、进程结束状态、Job 活跃数、测量记录；九轮检查均通过。入场检查不能证明运行全程后台负载低于门槛；运行时系统总 CPU 包含基准进程。
- 四个数据集的输入文件在本批前、Cohere 抽样 ground-truth 预检后、批次后哈希相同，并与 v3 边界记录一致。独立审阅者另对当前输入文件逐项重新哈希；边界快照不能排除运行中变化后恢复。
- TriviumDB 基准可执行文件、库文件指纹、脚本及指定计算环境变量与 v3 边界记录一致；系统 DLL 和所有潜在环境因素未被完整指纹化。
- 两个基线保存了逐向量 ID/命中；独立审阅者先抽样复算 24 份 NPZ，另一套独立排序双指针脚本随后对全部 72 份 NPZ、144 万条查询逐行复算，结果均与同一份绑定 GT 一致。该复核不是对全部查询重新执行精确搜索。原版 TriviumDB 仅输出每次完整查询批次的 QPS/召回，不含逐向量 ID 或单条延迟。[独立复核记录](../target768-independent-audit-20261106/summary.json)。
- TriviumDB 查询计时包含 GT 命中统计，两个基线的查询计时不含召回计算。TriviumDB `hot_bytes` 与基线公式估算口径不同，不能宣称精确内存节省倍数。
