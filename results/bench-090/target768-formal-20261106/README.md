# Cohere 768d three-engine replay: incomplete publication gate

This directory preserves a user-requested targeted 768d / 1M-vector replay. **It did not pass the preregistered stability gate and is not a publishable comparison.** The local run completed collection but marks `publication_permitted: false` and requires independent review. The TriviumDB group exceeded the preregistered sample-CV threshold at multiple ef values; the hnswlib and FAISS-HNSW groups individually passed. Consult [summary.json](summary.json) and [decisions.jsonl](decisions.jsonl) for the actual outcomes, rather than inferring a passed batch from the presence of files.

## Design and interpretation

[preregistration.json](preregistration.json) fixes one group per engine, three independent builds per group, one complete tiled 20K query batch at each ef per build, 16 threads, graph parameters and the target-recall/interpolation rules. The three previous complete Cohere/TriviumDB groups in [the original v3 batch](../replay-full-v3-20261105/README.md) all failed the stability threshold. This targeted batch was requested after those failures; it does not replace them. Repeated campaigns can introduce selection bias: publish all attempts and never describe a later favorable group as proof that the underlying cause was fixed.

The per-run records under `groups/` include raw benchmark results, gate checks, supervisor and system-load observations, logs, and failures. Independent review checked all nine recorded runs, ground-truth/interpolation, admission and Job records; the TriviumDB sample CV exceeded 8% at ef 10 (11.113%), 15 (13.340%), 80 (8.851%), and 120 (9.990%). One reviewer independently recomputed per-query ground-truth hits for 24 of the 72 baseline NPZ archives. A second standalone audit used sorted scalar two-pointer matching to verify all 72 archives against the same bound ground truth; see [the independent audit](../target768-independent-audit-20261106/README.md). Neither check recomputes exact-search ground truth for all queries. Hnswlib and FAISS-HNSW NPZ archives retain per-query labels and hit counts; the original TriviumDB benchmark emits batch-level QPS and recall, not individual query IDs or per-query latency. The workload is tiled, so 20K entries are not 20K independent queries. TriviumDB timing includes ground-truth hit counting, while baseline timing excludes recall calculation.

Input hashes bind the recorded files at the preflight and final boundaries; the preflight is sampled, not an exhaustive ground-truth proof. Admission CPU is measured before each worker; during-run total system CPU includes the benchmark, so it cannot by itself prove background isolation. The cooperating-runner mutex and process scans have documented cross-session and inaccessible-process limits. Other dimensions are from an earlier session. Boundary hashes cannot exclude changes subsequently restored; system DLLs are not fingerprinted. See preregistration for the exact limits.

TriviumDB reports `hot_bytes`, whereas baseline index memory is estimated by formula. They are different measures and cannot support a precise memory-savings claim. This targeted replay does not resolve the independently observed P1 provenance assertion, release fault-suite compile crash, or RSS soak failures; see [the P1–P6 review](../replay-review-20261105/README.md). Do not represent the overall test suite or release gate as passed.

## Files, privacy, and exact bytes

[FILE-MANIFEST.json](FILE-MANIFEST.json) maps every copied source to published SHA-256, byte length and any transformations. All per-query NPZ archives and unredacted raw results retain exact source bytes. Text copies containing local personal/workspace paths are explicitly path-redacted; numeric measurement values and failure records are preserved. Original private files remain on the benchmark host; datasets and the benchmark executable are not included. Hashes embedded inside original records refer to private source bytes and, for path-dependent structures, original paths; where a text copy was redacted, use the manifest's source/published mapping.

`scripts/` contains byte-identical snapshots of the six execution scripts, each with an archival `.snapshot` suffix; their hashes match the preregistration. These are evidence, not ready-to-run entry points. The `.gitattributes` file prevents Git newline conversion from modifying evidence bytes. The manifest does not hash itself, this README, or `.gitattributes`.
